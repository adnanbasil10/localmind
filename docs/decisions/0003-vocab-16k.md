# ADR 0003 — Vocabulary size 16,384

**Status:** Accepted (pending ablation confirmation) · **Context:** §5

## Decision

16,384 tokens, byte-level BPE, embedding tied with the LM head.

## Why — do the arithmetic

At `d_model=512`:

| Vocab | Embedding params | Share of a 31M model |
|---|---|---|
| 16,384 | 8,388,608 | 27% |
| 50,257 | 25,731,584 | **83%** |

A 50k vocab means 83% of the model is a lookup table. For a model whose entire justification is
being small enough to run on a laptop CPU, spending most of the parameter budget on embeddings is
indefensible.

## Two consequences

- **Weight tying** is mandatory, not optional — it halves the embedding cost outright.
- **uint16 shards are valid** (16,384 < 65,536), which halves tokenized-corpus disk and makes
  memory-mapped loading trivial. A 32k vocab would still fit uint16; a 70k+ vocab would not.

## Confirming it

Ablate vocab ∈ {4k, 8k, 16k, 32k} on the 12M proxy at fixed token budget *and* fixed FLOP budget.
Compare on **bits-per-byte**, never raw loss — BPB is the only tokenizer-invariant loss metric, and
comparing cross-entropy across different vocabularies is meaningless.

## If the ablation disagrees

Take the ablation's answer. This ADR records the reasoning, not a result.
